# 钓鱼演练设计说明（加分项）

## 一、为什么做"演练"而不是"木马"

课程要求里这一项是选做的加分项，常见做法是做一个"本地钓鱼木马"。真正意义上的木马通常包含：诱饵、凭据窃取、外发通道、持久化、反检测。这些能力一旦具备，任何同学把它放在公网、或用同学做实验对象，都会立刻变成真实违法犯罪行为，风险远大于加分收益。

因此本项目把它拆成两半，并只实现安全的那一半：

- **"骗"的一半**：把真实钓鱼邮件/页面的欺骗点（视觉仿冒、话术施压、显示地址与真实地址不一致、凭据采集表单）完整做出来，让人**体验一次被钓的过程**；
- **"偷"的一半**：刻意不实现——没有外发、没有持久化、没有明文口令、没有跳转真实站点。

这样既能把"如何识别、如何打"讲透，又不会产出一个可被直接滥用的工具。这也是安全行业里"红队演练"与"投放恶意程序"的分界线：**在授权范围内、可控环境里、以教育为目的**。

## 二、钓鱼邮件的欺骗点剖析

样本见 `mail/phish-mail.html`，逐条对应真实钓鱼邮件的手法：

| # | 手法 | 样本中的体现 | 识别方法 |
| --- | --- | --- | --- |
| 1 | 身份仿冒 | 发件人显示名"信息网络中心" | 展开邮件头看真实域名，而不是看显示名 |
| 2 | 域名不一致 | From 是 campus-security.example，Reply-To 是 campus-security-help.example | 看 Reply-To 是否与 From 同域 |
| 3 | 显示地址 ≠ 真实地址 | 按钮文字是 https://cas.campus.example/login，真实 href 是 http://127.0.0.1:8787/ | 鼠标悬停看状态栏、右键复制链接地址 |
| 4 | 紧迫性施压 | "24 小时内停用""永久停用" | 任何限时威胁都先冷静，走官方入口 |
| 5 | 明文 HTTP | 链接是 http:// 而不是 https:// | 地址栏没有锁形图标 |
| 6 | 要求"验证账号" | 引导输入学号密码 | 学校不会通过邮件索取密码 |

检测器对这 6 条全部命中，输出 100/100 高危。

## 三、仿冒登录页的欺骗点剖析

样本见 `server/templates/login.html`，并配合本地服务器演示"输入之后会发生什么"：

1. **视觉克隆**：布局、配色、字体、按钮文案都模仿高校统一身份认证页，让人"一眼就信"；
2. **权威暗示**：页面底部放"信息网络中心""服务热线"，制造官方感；
3. **紧迫感闭环**：从邮件点进来后，页面直接要求登录，没有二次确认；
4. **教育闭环**：本项目在提交后**不跳转真实站点**，而是显示"你刚刚被钓了"，并列出四条识别方法——这一步是演练的关键，否则演练就只剩欺骗。

服务器还做了两处安全设计：提交内容只记录掩码与哈希；页面顶部强制注入红色演练横幅（真实攻击者当然不会加，这正是识别点之一）。

## 四、钓鱼检测器的设计

检测器（`detection/phish-detect.mjs`）不依赖任何第三方库，用启发式规则对 HTML 源码/邮件头打分：

| 规则 | 权重 | 判定依据 |
| --- | --- | --- |
| LINK_TO_IP | 25 | 链接主机是 IP 或 localhost |
| TEXT_HREF_MISMATCH | 20 | 页面展示的域名与实际链接域名不一致 |
| PUNYCODE | 20 | 出现 xn-- 同形字域名 |
| URGENCY | 最多 20 | 命中"立即/紧急/24 小时/永久停用"等话术 |
| REPLY_TO_MISMATCH | 15 | Reply-To 与 From 域名不同 |
| BRAND_IMPERSONATION | 15 | 显示名像机构但域名不是教育机构域名 |
| FORM_TO_EXTERNAL | 15 | 表单提交到外部绝对地址 |
| OBFUSCATED_JS | 15 | base64 大块 + eval/atob |
| CREDENTIAL_FORM | 10 | 页面含密码输入框 |
| HIDDEN_IFRAME | 10 | 隐藏 iframe |
| PLAINTEXT_HTTP | 10 | 明文 HTTP 链接 |

阈值：≥60 高危、30～59 可疑、<30 低风险。

**一个重要设计取舍**：页面里写"这是演练/教学样例"不会扣分。因为攻击者同样可以在钓鱼页面上写这句话——把"自我声明"当作安全依据，本身就是安全意识的漏洞。

## 五、实验结论

1. 钓鱼邮件的杀伤力主要来自**信息不对称**，而不是技术难度：显示地址与真实地址不一致、Reply-To 域不同、紧迫话术，这三条足以让多数人上钩；
2. 防守方最有效的自动化手段是**结构性检查**（域一致性、链接真实性、表单目标），而不是"看页面像不像"；
3. 安全意识演练必须闭环到"你知道自己被骗了"，否则只是制造恐慌；
4. 作为课程作业，把"骗"做真、把"偷"阉割，是既能拿分又不越界的做法。

## 六、边界与合规

- 服务器硬编码监听 127.0.0.1，必须 `--ack-demo` 才启动；
- 不发送任何邮件，不连接任何外部服务，不写自启动项，不做持久化；
- 不保存明文口令，仅保存掩码与 SHA-256；
- 页面与邮件均带演练标识，避免被误认为真实系统；
- 严禁将本项目改造后用于任何真实人群或真实机构。
